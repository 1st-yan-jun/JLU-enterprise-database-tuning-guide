### 第 1 步：手动创建 ARTISTS 表（核心 DDL）
* **课件 PPT 对应知识点**：
  * **Slide 27-28（LOB 参数）**：`bio clob (100K) logged compact`（100K 文本大对象，记录日志并紧凑压缩）；`picture blob (500k) not logged compact`（500K 图片二进制大对象，由于超大为了避免日志暴涨，选用 `NOT LOGGED`，但采用 `COMPACT` 压缩）。
  * **Slide 30（表空间规划）**：常规数据放 `DMS01`，主键索引放 `DMS02`，大对象数据独立存放于 `DMS03`。
* **执行命令**：
  ```cmd
  db2 "create table artists (artno smallint not null, name varchar(50), classification char(1) not null, bio clob(100K) logged compact, picture blob(500k) not logged compact, primary key (artno)) in dms01 index in dms02 long in dms03"
  ```
* **预期输出**：
  ```text
  DB20000I  SQL 命令成功完成。
  ```
* **截屏要点**：
  * 截取输入完整建表 SQL 并回显 `DB20000I SQL 命令成功完成` 的命令行窗口。
* **PPT 思考题深度拓展（Slide 31）**：
  > **问：一共有 5 列，为什么只有 `artno` 和 `classification` 可以作为主键的备选？**  
  > **答**：  
  > 1. 主键列的基本前提是必须显式指定 `NOT NULL`，且业务上不允许存在空值；而 `name` 列未定义非空约束，且现实中容易存在同名。  
  > 2. `bio`（CLOB）与 `picture`（BLOB）属于**大对象（LOB）数据类型**。在关系型数据库理论与 DB2 核心机制中，**严格禁止在 LOB 列上建立主键约束或唯一索引**。  
  > 3. 因此全表中只有非 LOB 且具有非空限制的 `artno` 与 `classification` 具备主键备选资格；其中 `artno`（艺术家编号）具备业务实体的唯一性，是最佳主键。

### 第 3 步：从系统目录查询索引属性（UNIQUERULE 解析）
* **课件 PPT 对应要点（Slide 38）**：
  “注意单引号必须是英文单引号，UNIQUERULE 中的 P 一定要大写。”
  - `UNIQUERULE = 'U'`：唯一索引（Unique，不允许重复值）；
  - `UNIQUERULE = 'D'`：非唯一索引（Duplicates allowed，允许重复值）；
  - `UNIQUERULE = 'P'`：主键系统自动生成的索引（Primary Key）。
* **执行命令**：
  ```cmd
  db2 "select substr(tabname,1,18) as tabname, uniquerule, substr(indname,1,18) as indname, substr(colnames,1,30) as colnames from syscat.indexes where indschema=user order by tabname, indname"
  ```
* **预期输出表格（实测标准输出为 2 条记录）**：
  ```text
  TABNAME            UNIQUERULE INDNAME            COLNAMES
  ------------------ ---------- ------------------ ------------------------------
  ALBUMS             U          ITEMNO             +ITEMNO
  STOCK              D          ITEM               +ITEMNO

    2 条记录已选择。
  ```
  *(注：为什么只有 2 条输出？原因解析：我们在 SQL 中指定了过滤条件 `WHERE indschema = user`，即只查当前用户显式创建的索引模式。而 `ARTISTS` 表的主键索引是由系统底层自动创建的，其模式名归属于 `SYSIBM`。因此当前用户自己创建的索引正好就是这 2 个：第 1 步在 `STOCK` 上创建的常规索引 `ITEM (D)` 和第 2 步在 `ALBUMS` 上创建的唯一索引 `ITEMNO (U)`。这与随后的官方比对文件 **`indchk.master`（内容恰好就是这 2 条记录）100% 完全吻合**！)*
* **截屏要点**：
  * 截取查询结果，清晰展示 `ALBUMS (U)` 和 `STOCK (D)` 这 2 条记录。

## 📝 第八部分：Section 7 - Create a Trigger（创建触发器）

---

### 第 1 步：创建补货触发器 `reorder`
* **课件 PPT 对应知识点（Slide 46-48, 61）**：
  * 触发器三要素：
    - **Rule（事件）**：`AFTER UPDATE OF qty ON stock`
    - **Condition（条件）**：`WHEN (n.qty <= 5)`
    - **Action（动作）**：`INSERT INTO reorder VALUES (n.itemno, CURRENT TIMESTAMP)`
* **执行命令**：
  ```cmd
  db2 "create trigger reorder after update of qty on stock referencing new as n for each row mode db2sql when (n.qty <= 5) insert into reorder values (n.itemno, current timestamp)"
  ```
* **预期输出**：

### 💡 课件 PPT 重点思考题深度解答（Slide 63 必背考点！）
> **【教师 PPT 提问】**：  
> 触发器的条件是 `n.qty <= 5`。假设商品 A 原来 `qty = 7`。客户 1 买走 2 件，`qty = 5`，触发 1 次；客户 2 随后买走 2 件，`qty = 3`，会再次触发。  
> **思考：如何修改触发器定义，能使得该商品在库存持续减少时“只有第一次触发”？**  
>
> **【高分标准答案】**：  
> **方案一（通过新旧值对比，最推荐⭐⭐⭐）**：  
> 在 `REFERENCING` 子句中同时引用旧行与新行：`REFERENCING OLD AS o NEW AS n`，并将 `WHEN` 条件修改为：  
> ```sql
> WHEN (o.qty > 5 AND n.qty <= 5)
> ```  
> *原理解析*：这样只有当库存是**从大于 5 首次跨越阈值降至 5 及以下**时，条件才为真并触发；随后的再次扣减（从 5 变为 3），因为旧值 `o.qty` 已经不大于 5，条件为假，不会重复触发！  
>
> **方案二（通过防重查询）**：  
> 在 `WHEN` 条件中增加排重检查：  
> ```sql
> WHEN (n.qty <= 5 AND NOT EXISTS (SELECT 1 FROM reorder WHERE itemno = n.itemno))
> ```
