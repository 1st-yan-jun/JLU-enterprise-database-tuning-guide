### 第 2 步：在 `create database` 命令中可以指定哪些信息？

* **原题要求**：
  
  > *2. What information can you specify on the create database command?*

* **标准答案（直接填入报告）**：
  根据 `CREATE DATABASE` 语法定义，创建数据库时可以指定以下关键信息：
  
  1. **数据库名称与别名（Database Name & Alias Name）**：指定数据库的物理名称及客户端访问的别名（未指定别名时默认与数据库名相同）。
  2. **存储路径（Storage Path / DBPATH）**：通过 `ON` 参数指定自动存储（Automatic Storage）路径，或通过 `DBPATH ON` 指定数据库控制文件与目录元数据的存放驱动器/路径。
  3. **自动存储管理（AUTOMATIC STORAGE YES / NO）**：指定是否启用自动存储管理机制（DB2 9 默认启用）。
  4. **默认表空间定义（Default Table Spaces Definition）**：可自定义系统目录表空间（`CATALOG TABLESPACE`）、默认用户表空间（`USER TABLESPACE`）以及系统临时表空间（`TEMPORARY TABLESPACE`）的容器类型、区段大小及页面大小。
  5. **代码集与区域设置（CODESET & TERRITORY）**：指定数据库使用的字符编码集（如 UTF-8、GBK）和国家区域代码。
  6. **字符排序规则（COLLATE USING）**：指定字符比较和排序方式（如 `SYSTEM`、`IDENTITY`、`IDENTITY_16BIT`）。
  7. **页面大小与区段默认值（PAGESIZE & DFT_EXTENT_SZ）**：指定数据库默认缓冲池页面大小（如 4K、8K、16K、32K）及默认 Extent 区段大小。
  8. **安全性与权限限制（RESTRICTIVE）**：是否创建为“限制性数据库”（若指定该项，系统不会自动向 PUBLIC 组授予任何默认连接和访问权限）。
  9. **注释说明（WITH "comment-string"）**：为数据库添加描述性注释文本。

### 第 3 步：创建数据库时默认创建哪些表空间？

* **原题要求**：
  
  > *3. Based on what you learned in lecture, what table spaces are created when a database is created?*

* **标准答案（直接填入报告）**：
  根据课堂讲解与 DB2 体系架构，创建数据库时会自动创建以下 **3 个核心表空间**（在实测环境中包含 4 个）：
  
  1. **`SYSCATSPACE`（系统目录表空间）**：用于存放该数据库的系统目录表、目录视图、触发器、约束定义及所有元数据（Metadata）。
  2. **`TEMPSPACE1`（系统临时表空间）**：供数据库管理器执行复杂的 SQL 操作（如内部排序 SORT、哈希连接 HASH JOIN、创建临时索引、表重组 REORG 等）时作为工作区使用。
  3. **`USERSPACE1`（默认用户表空间）**：用于存放最终用户创建的所有业务数据表、索引及用户定义对象。
  4. *(注：在 DB2 9 Express-C 实测中，还会默认创建第 4 个用于管理工具的表空间 **`SYSTOOLSPACE`**，用于存放 DB2 自带管理工具与维护任务的控制表。)*

### 第 4 步：默认表空间使用 SMS 还是 DMS？

* **原题要求**：
  
  > *4. What type of table space, SMS or DMS, will your database use by default for these default table spaces?*

* **标准答案（直接填入报告）**：
  在 DB2 9 Express-C 中（由于启用了 Automatic Storage 自动存储）：
  
  - **`SYSCATSPACE`**：**DMS**（数据库管理空间，类型为常规 Regular 表空间，由自动存储自动管理）。
  - **`TEMPSPACE1`**：**SMS**（系统管理空间，类型为系统临时 System Temporary 表空间）。
  - **`USERSPACE1`**：**DMS**（数据库管理空间，类型为大型 Large 表空间，由自动存储自动管理）。
  - **`SYSTOOLSPACE`**：**DMS**（数据库管理空间，类型为大型 Large 表空间）。

### 第 5 步：创建数据库前的默认值预判

* **原题要求**：
  
  > *5. Before we create our lzb_1019 database, remember what you learned in lecture about what some of the defaults will be.*

* **各项标准回答（直接填入报告）**：
  
  - **• What is the default path that the database will be created on?**  
    由数据库管理器配置（DBM CFG）参数 `DFTDBPATH` 决定。在 Windows 环境下，默认为 DB2 安装驱动器的根目录（如 `C:`）。
  - **• What will be the default table space type (SMS or DMS) for the table spaces that will be created to house User Tables, Catalog Tables, and Temporary Tables?**  
    Catalog 表空间（`SYSCATSPACE`）为 **DMS**；User 表空间（`USERSPACE1`）为 **DMS**；Temporary 表空间（`TEMPSPACE1`）为 **SMS**。
  - **• What are the default Extent and Prefetch sizes?**  
    默认 `EXTENTSIZE`（区段大小）为 **32** 页；默认 `PREFETCHSIZE`（预取大小）为 **AUTOMATIC**。
  - **• What are the default Territory, Code Set and Collating Sequence values?**  
    默认派生自宿主操作系统的区域设置（Locale）。英文系统下为 Territory: `US`，Code Set: `UTF-8`（或 `1252`），Collating Sequence: `IDENTITY`；中文系统下为 Territory: `CN`，Code Set: `GBK`。

### 第 9 步：目录条目类型 `Indirect` 代表什么？

* **原题要求**：
  
  > *9. What does a Directory entry type of Indirect mean?*

* **标准答案（直接填入报告）**：
  **`Indirect`（间接）** 表示该数据库是**本地数据库**，其物理数据文件存放在当前 DB2 实例所在的主机磁盘上。该条目间接指向本机的本地数据库目录（Local Database Directory），应用程序可直接由本地数据库引擎调度访问。

### 第 10 步：目录条目类型 `Remote` 代表什么？

* **原题要求**：
  
  > *10. What does a Directory entry type of Remote mean?*

* **标准答案（直接填入报告）**：

### 第 9 步：表空间 ID 分布、DMS 可用页数计算与 SMS/DMS 区别（重要理论大题！）

* **原题要求**：
  
  > *9. What ID numbers are associated with each of the table spaces? How many usable pages are there in the DMS table spaces? List a few differences between SMS and DMS table spaces.*

* **标准答案（直接填入报告）**：
  
  #### 1. 各表空间对应的 ID 编号：
  
  - **ID 0**：`SYSCATSPACE`（系统默认目录，DMS）
  - **ID 1**：`TEMPSPACE1`（系统默认临时，SMS）
  - **ID 2**：`USERSPACE1`（系统默认用户，DMS）
  - **ID 3**：`SYSTOOLSPACE`（系统工具，DMS）
  - **ID 4**：`DMS01`（手动创建的 DMS 表空间）
  - **ID 5**：`DMS02`（脚本创建）
  - **ID 6**：`DMS03`（脚本创建，Long DMS）
  - **ID 7**：`DMS04`（脚本创建）
  - **ID 8**：`DMS05`（脚本创建）
  - **ID 9**：`DMS06`（脚本创建）
  - **ID 10**：`SMS01`（脚本创建的 SMS 表空间）
  
  #### 2. DMS 表空间中可用页数（Usable Pages）分析：
  
  - 以 `DMS01` 为例：总计页数为 **1006 页**（或实测预分配 1000 页），而可用页数显示为 **1002 页**（或 996 页），比总页数正好**少了 4 页**。
  - **原因**：这 4 页正好等于定义该表空间时的 `EXTENTSIZE`（区段大小 = 4 页）。DMS 容器必须预留至少 1 个完整的 Extent 用于存储表空间的**元数据开销**，包括容器标记（Container Tag）、区段映射页（Extent Map Page, EMP）以及表空间头部控制结构。因此可用页数 = 总页数 - 元数据保留页。
  
  #### 3. SMS 与 DMS 表空间的核心区别对比表：
  
  | 对比维度         | SMS（系统管理表空间）                      | DMS（数据库管理表空间）                            |
  |:------------ |:--------------------------------- |:---------------------------------------- |
  | **存储空间分配**   | **按需动态分配**：写入数据时由操作系统文件系统动态追加文件大小 | **预先分配**：创建表空间时即一次性占满固定大小的磁盘文件或裸设备       |
  | **底层管理主体**   | 由操作系统底层文件系统负责空间调度与分配              | 由 DB2 数据库引擎直接接管底层存储与 I/O 调度              |
  | **容器存储类型**   | 只能使用操作系统**目录路径（Path）**            | 支持使用**文件（File）**或**裸设备（Device）**         |
  | **数据分离支持**   | 表的数据、索引、长对象（LOB）**必须存放在同一个表空间**   | **支持彻底分离**：表数据、索引、LOB 可存放在不同的专用表空间       |
  | **I/O 性能表现** | 存在文件系统缓存开销和磁盘碎片，性能相对较低            | 绕过文件系统开销，支持直接 I/O（Direct I/O），**访问性能极高** |
  | **空间动态扩充**   | 依赖宿主文件系统的剩余空间，不能手工添加容器            | 支持通过 `ALTER TABLESPACE` 在线扩展容器大小或动态追加新容器 |
